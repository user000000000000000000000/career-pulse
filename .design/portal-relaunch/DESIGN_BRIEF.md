# Design Brief: CareerPulse — светлая/тёмная тема (пилот: Главная + Результаты)

## Problem

Сейчас у платформы одна визуальная версия — тёмная неоновая. Она хорошо считывается подростком как «цифровой, современный» продукт, но для родителя (который принимает решение платить за консультацию, читает отчёт вместе с ребёнком, возможно печатает/пересылает скриншот) тёмный интерфейс на первом впечатлении читается скорее как «геймерское приложение», чем как образовательный/психометрический инструмент, которому можно доверять.

## Solution

Два полноценных оформления одного и того же портала, переключаемых пользователем: **светлое — официальное**, первое впечатление по умолчанию для нового посетителя (внушает доверие родителю); **тёмное — цифровое/молодёжное** (уже существует и полностью реализовано), доступно по явному переключению. Не два разных сайта — одна и та же структура, разметка и контент, разные токены цвета/типографики.

## Experience Principles

1. **Доверие по умолчанию, энергия по выбору** — новый посетитель видит спокойный, официальный светлый вид; тёмный — акт осознанного выбора, а не то, что пугает с порога.
2. **Один портал, не два сайта** — переключение темы не должно менять структуру страницы, только облицовку. Пользователь должен узнавать интерфейс в обеих темах.
3. **Ничего не теряем при переключении** — уже вложенный труд в тёмную тему (маскот-лиса, графики результатов, карточки) переносится как есть, адаптируется, а не переделывается с нуля.

## Aesthetic Direction

- **Философия**: светлая тема — «спокойный официальный SaaS для образования» (мягкие нейтральные фоны, сдержанные акценты, много воздуха); тёмная — уже существующий «неоновый цифровой» стиль, не меняется по духу.
- **Тон**: светлая — серьёзно, дружелюбно-профессионально; тёмная — энергично, современно.
- **Референсы**: присланный ПДФ-макет (светлая часть — общая идея мягких градиентных пятен и карточек на светлом фоне, кольца/точечная сетка как декор) — использовать как вдохновение для декоративных элементов и композиции, не копировать один в один цвета/шрифт.
- **Анти-референсы**: светлая тема не должна превращаться в безликий корпоративный синий SaaS — акцентные цвета остаются те же (бирюза/фиолет/оранжевый/золото), просто в осветлённой/приглушённой версии, чтобы бренд узнавался в обеих темах.

## Existing Patterns

- **Типография**: сейчас Bebas Neue (заголовки) + Manrope (текст) + JetBrains Mono (лейблы/цифры), загружены через Google Fonts в `index.html`. **Решение по гриллу: переходим на Unbounded** для заголовков вместо Bebas Neue — более геометричный, современный, совпадает с присланным референсом. Manrope и JetBrains Mono остаются.
- **Цвета**: `frontend/src/index.css` — токены `--ink/--card/--card2/--accent(#00e5c8)/--violet(#7b5cf0)/--ember(#ff6b35)/--gold(#f5c842)/--text/--sub/--ghost/--line`. Это единственная тема сейчас (тёмная, без альтернативы) — задача превратить в пару токен-наборов.
- **Компоненты**: `components/UI/` — Button, Card, Input, ProgressBar, RadioGroup (переиспользуемые, используются по всему приложению — менять их один раз, эффект везде). Плюс `components/Mascot/` (лиса, 4 состояния) — уже частично токен-зависима через CSS-переменные в `mascot.css`.
- **Много inline-стилей с хардкод-цветами** — особенно в `DiagResults.jsx` (`'#00e5c8'`, `'#7b5cf0'` и т.д. напрямую в `style={{}}`), а не через `var(--accent)`. Это главный технический риск для смены темы — такие места не подхватят светлую палитру автоматически, нужен отдельный проход по их переводу на переменные.

## Component Inventory

| Component | Status | Notes |
|---|---|---|
| Токены (`index.css`) | Modify | Добавить светлый набор + `data-theme` / `prefers-color-scheme` механизм, дефолт — светлая |
| `ThemeToggle` | New | Переключатель темы, персист в localStorage, в топ-баре |
| `Button/Card/Input/ProgressBar/RadioGroup` | Modify | Проверить, что все цвета через `var(--token)`, не хардкод |
| `Mascot`/`FoxSVG` | Modify | Обводка/тени карточки-облачка уже токен-driven; сама лиса — фиксированный цвет, не завязан на тему (окей оставить) |
| `Landing.jsx` | Modify | Пилотная страница №1 |
| `DiagResults.jsx` | Modify | Пилотная страница №2, требует чистки хардкод-цветов в inline-стилях |
| Шрифт Unbounded | New | Добавить в `index.html` Google Fonts подключение, завести как `--font-display` |

## Key Interactions

- Переключатель темы в топ-баре (иконка солнце/луна) — клик мгновенно меняет `data-theme` на `<html>`, без перезагрузки страницы, сохраняет выбор в `localStorage` на будущие визиты.
- Новый посетитель без сохранённого выбора всегда видит светлую тему (не зависит от системных настроек ОС — так решили на гриле).

## Responsive Behavior

Без изменений относительно текущей логики брейкпоинтов Landing/DiagResults — тема не влияет на структуру/раскладку, только на цвет/типографику.

## Accessibility Requirements

- Контраст текста к фону — минимум AA (4.5:1) в обеих темах, включая новую светлую (нейтральные фоны сейчас выбраны тёпло-серыми, не чисто-белыми — важно перепроверить реальные hex после подбора в Design Tokens фазе).
- `:focus-visible` уже есть глобально — сохранить в обеих темах.
- Переключатель темы — доступен с клавиатуры, с понятным `aria-label`.

## Out of Scope

- 10 блоков диагностики (`Block1Anketa.jsx` … `Block10Letter.jsx`), Атлас, Личный кабинет, страницы авторизации/легал — не трогаем в этом пилоте. Отдельный проход после того, как пилот утверждён.
- Изменение самой структуры/контента страниц (это не редизайн разметки, а новая облицовка).
- Изменение дизайна маскота-лисы (форма/анатомия) — только его окружение (карточки/фон) подстраивается под тему.
